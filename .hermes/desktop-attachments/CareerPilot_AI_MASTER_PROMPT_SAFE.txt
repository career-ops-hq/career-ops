# CAREERPILOT AI — MASTER DEVELOPMENT SPECIFICATION
# SAFE EXECUTION CONTROL — PRESERVE EVERYTHING

## ABSOLUTE RULES

1. Do not delete any existing file, feature, integration, configuration, user data, database, Git history, documentation, or working code.
2. Do not overwrite the original project.
3. Do not move or rename the original project folder until:
   - a verified backup exists,
   - Git status is recorded,
   - the application has been built and tested,
   - the user has explicitly approved the move or rename.
4. Treat the existing project as the source of truth. Inspect the real repository before making assumptions.
5. Make all development changes in a new Git branch.
6. Use additive development, migrations, adapters, feature flags, and compatibility layers instead of destructive replacement.
7. Before changing a file, record why it must change.
8. After changing a file, verify that the file was actually modified and that the application still builds.
9. Never report a feature as completed unless it is:
   - implemented,
   - connected to the UI,
   - tested,
   - documented,
   - verified in a working build.
10. Stop and ask for approval before any destructive, irreversible, paid, publishing, account-connection, credential, database-format, or administrator-level action.

## EXECUTION METHOD

Work milestone by milestone.

For every milestone:

1. Inspect the current implementation.
2. Create or verify a backup.
3. Record Git status.
4. Create or use the correct feature branch.
5. Write an implementation plan.
6. Implement only the current milestone.
7. Run lint, type checking, tests, build, and smoke test.
8. List every changed file.
9. Document working and non-working parts.
10. Create a Git commit only after verification.
11. Do not continue to the next milestone until the current milestone is stable.
