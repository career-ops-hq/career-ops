## career-ops आपके लिए क्या करता है

एक नौकरी पेस्ट करें। यह बताता है कि वह रात लगाने लायक है या नहीं।

- **अभी भी खुली है?** आपके एक शब्द लिखने से पहले ही यह जाँच लेता है कि पोस्टिंग अभी भी लाइव है।
- **आप नहीं?** यह आपके असली CV के मुकाबले रोल को स्कोर करता है और कमज़ोर फ़िट को छोड़ने को कहता है। आप इसे ओवरराइड कर सकते हैं।
- **करने लायक?** यह CV, कवर लेटर और जवाबों का ड्राफ़्ट बनाता है। आप उन्हें पढ़ते हैं। आप उन्हें भेजते हैं।
- **किससे बात करूँ?** यह सही व्यक्ति ढूँढता है और संदेश का ड्राफ़्ट बनाता है। इसे कभी भेजता नहीं।
- **यह सब जाता कहाँ है?** हर आवेदन आपकी मशीन पर रहता है। हमारे पास कुछ भी अपलोड नहीं होता।
- **मुझे क्या सीखना चाहिए?** लगातार कई "ना" के बाद, यह कमी का नाम बताता है।

शुरुआती रन खुरदुरे होते हैं। यह अभी आपको जानता नहीं। इससे बात करें: आपका CV, आप क्या चाहते हैं, क्या नहीं। इसे एक रिक्रूटर का पहला हफ़्ता समझें।

पहली बार चलाने पर यह सब कुछ चैट में पूछ लेता है। हाथ से कुछ भी कॉन्फ़िगर नहीं करना।

## career-ops क्या नहीं करता

- **आवेदन अपने आप सबमिट करना।** यह हर फ़ील्ड के जवाब का ड्राफ़्ट बनाता है; आप जाँचते हैं और Submit दबाते हैं। स्क्रिप्ट कभी POST नहीं करती (`prepare-application.mjs`)।
- **ईमेल भेजना।** सिर्फ़ ड्राफ़्ट। इस पूरे कोडबेस में कहीं भी मेल भेजने का कोई ज़रिया नहीं है।
- **बाहर डेटा भेजना।** कोई टेलीमेट्री नहीं, हमारा कोई बैकएंड नहीं। आपका CV आपकी मशीन से सीधे आपके चुने हुए AI प्रोवाइडर तक जाता है, और कहीं नहीं। एकमात्र सार्वजनिक रिकॉर्ड यही रिपॉज़िटरी है: `HIRED.md` और इसके issues।
- **4.0/5 से नीचे आवेदन के लिए धकेलना।** यह आपको मना करेगा। आप इसे नज़रअंदाज़ कर सकते हैं, और यह बता देगा।

यह आपके CV को दोबारा लिखता है; उसे कभी गढ़ना नहीं चाहिए। कोड में एक जाँच ऐसी PDF को रोक देती है जिसके आँकड़े या तथ्य न आपके CV में हैं, न आपके article digest में, लेकिन दोबारा लिखे गए हर वाक्य को यह अभी नहीं परख सकती। भेजने से पहले हर CV पढ़ें। विवरण [FAQ](#अक्सर-पूछे-जाने-वाले-प्रश्न-faq) में।

## Quick Start

**सबसे तेज़ तरीक़ा, एक ही कमांड से:**

```bash
npx @santifer/career-ops init
```

> 💡 `npx` [Node.js](https://nodejs.org) के साथ आता है: यह इंस्टॉलर एक बार चलाता है,
> बिना कुछ ग्लोबली इंस्टॉल किए। अभी Node नहीं है? पहले उसे इंस्टॉल करें।
> (पहले से Claude Code / Codex CLI इस्तेमाल कर रहे हैं? तो आपके पास पहले से है।)

यह नवीनतम रिलीज़ को `./career-ops` में क्लोन करता है और डिपेंडेंसी इंस्टॉल करता है। फिर:

```bash
cd career-ops
claude   # or codex / qwen / opencode / agy / grok — open your AI CLI here
```

**पहली बार लॉन्च पर career-ops सिर्फ़ चैट करके आपको सेटअप कराता है: आपका CV, प्रोफ़ाइल और लक्षित भूमिकाएँ। हाथ से कुछ भी संपादित नहीं करना।**

### ग्लोबल इंस्टॉल

```bash
npm i -g @santifer/career-ops
```

यह `career-ops` बाइनरी को ग्लोबली इंस्टॉल करता है ताकि आप `npx` के बिना `career-ops init [folder]` चला सकें। `init` इसकी इकलौती कमांड है: यह एक वर्कस्पेस तैयार करती है, और उसके बाद का सारा काम आपकी AI कोडिंग CLI के अंदर होता है (नीचे Usage देखें), इस बाइनरी के ज़रिए नहीं।

**कौन सा इस्तेमाल करें?**
- `npx @santifer/career-ops init`: पहली बार के लिए सबसे अच्छा; एक अलग प्रोजेक्ट फ़ोल्डर बनाता है।
- `npm i -g @santifer/career-ops`: अगर आप `npx` वाले रूप के बजाय `career-ops init` टाइप करना पसंद करते हैं। यह कोई और कमांड नहीं जोड़ता।

## Usage

अपनी AI CLI में किसी नौकरी का URL या विवरण पेस्ट करें। career-ops जाँचता है कि लिंक वाला पोस्टिंग अभी भी खुला है (पेस्ट किए गए टेक्स्ट में जाँचने के लिए कोई लिंक नहीं होता), उसे आपके CV के मुक़ाबले स्कोर करता है, रिपोर्ट लिखता है, PDF तैयार करता है और आपके tracker में एक पंक्ति जोड़ता है। ज़्यादातर दिनों के लिए इतना काफ़ी है। बाकी सब कुछ ऐसे mode हैं जिन्हें आप नाम से माँगते हैं।

### Mode कैसे माँगें

| CLI | `scan` कैसे माँगें |
| --- | --- |
| Claude Code, OpenCode, Qwen, Antigravity CLI (`agy`), Grok Build CLI | `/career-ops scan` |
| Pi | `/skill:career-ops scan` |
| Codex, Cursor या कोई और CLI | सामान्य भाषा में: "Run the career-ops scan mode" |

सिर्फ़ `/career-ops` लिखने पर कमांड मेन्यू दिखता है। सामान्य भाषा हर CLI में काम करती है।

ये सभी एक ही router, `.agents/skills/career-ops/SKILL.md`, और एक जैसी `modes/*.md` फ़ाइलें साझा करती हैं, इसलिए कोई भी CLI चलाए, mode एक जैसा ही व्यवहार करता है। Codex में स्लैश कमांड की गारंटी नहीं है: सामान्य भाषा में माँगें, या `codex exec "Evaluate this JD with career-ops auto-pipeline: https://company.com/jobs/123"` से एक prompt headless चलाएँ ([docs/CODEX.md](docs/CODEX.md))। हर समर्थित CLI में इसे कैसे चलाएँ, जिस CLI में headless कमांड है उसका वह कमांड, और Pi के `/trust` जैसे हर CLI के सेटअप नोट [docs/SUPPORTED_CLIS.md](docs/SUPPORTED_CLIS.md) में हैं।

## Pre-configured Portals

स्कैनर **100+ कंपनियों** के साथ आता है जो स्कैन के लिए तैयार हैं और प्रमुख जॉब बोर्ड्स पर **35+ सर्च क्वेरी** के साथ। `templates/portals.example.yml` को `portals.yml` में कॉपी करें और अपनी जोड़ें:

**AI Labs:** Anthropic, OpenAI, Mistral, Cohere, LangChain, Pinecone
**Voice AI:** ElevenLabs, PolyAI, Parloa, Hume AI, Deepgram, Vapi, Bland AI
**AI Platforms:** Retool, Airtable, Vercel, Temporal, Glean, Arize AI
**Contact Center:** Ada, LivePerson, Sierra, Decagon, Talkdesk, Genesys
**Enterprise:** Salesforce, Twilio, Gong, Dialpad
**LLMOps:** Langfuse, Weights & Biases, Lindy, Cognigy, Speechmatics
**Automation:** n8n, Zapier, Make.com
**European:** Factorial, Attio, Tinybird, Clarity AI, Travelperk

**खोजे जाने वाले जॉब बोर्ड:** 55+ प्रोवाइडर मॉड्यूल ATS API, बोर्ड-व्यापी फ़ीड, XML/RSS फ़ीड, markdown फ़ीड और लोकल पार्सर कवर करते हैं। पूरी तालिका के लिए [Supported job boards](docs/SUPPORTED_JOB_BOARDS.md) देखें।

डिफ़ॉल्ट रूप से `node scan.mjs` (यानी `npm run scan`) हर ATS फ़ीड जो लौटाती है उस पर भरोसा करता है। कुछ कंपनियाँ भूमिका बंद होने के बाद भी पुरानी पोस्टिंग अपने सार्वजनिक API में छोड़ देती हैं, इसलिए वे समाप्त एंट्रियाँ `pipeline.md` में लीक हो सकती हैं। API पास के बाद Playwright चलाने और समाप्त पोस्टिंग को पाइपलाइन में पहुँचने से पहले हटाने के लिए `--verify` दें:

```bash
node scan.mjs --verify          # zero-token discovery + Playwright liveness check
```

सत्यापन क्रमिक है और सिर्फ़ नए ऑफ़र पर (डीडुप के बाद) चलता है, इसलिए लागत सीमित रहती है।

## बाहरी डेटा डायरेक्टरी (वैकल्पिक)

डिफ़ॉल्ट रूप से, यूज़र-लेयर डेटा (जैसे `cv.md`, `portals.yml`, और `data/` / `reports/` / `output/` फ़ोल्डर) प्रोजेक्ट रूट फ़ोल्डर के अंदर रहता है।

अपना व्यक्तिगत डेटा कोड से अलग रखने के लिए (ब्रांच बदलना, अपडेट खींचना या कई प्रोफ़ाइल आज़माना आसान हो जाता है), आप इस प्राथमिकता क्रम से एक बाहरी डेटा डायरेक्टरी कॉन्फ़िगर कर सकते हैं:

1. **एनवायरनमेंट वेरिएबल:** `CAREER_OPS_ROOT` या `CAREER_OPS_DATA_DIR` एनवायरनमेंट वेरिएबल सेट करें:
   ```bash
   export CAREER_OPS_ROOT=~/my-career-data
   ```
2. **मार्कर फ़ाइल:** रिपॉज़िटरी रूट में एक `.career-ops-data` फ़ाइल बनाएँ जिसमें आपकी डेटा डायरेक्टरी का पाथ हो।
3. **डिफ़ॉल्ट:** रिपॉज़िटरी रूट।

तय हो जाने के बाद, सभी यूज़र फ़ाइलें उसी फ़ोल्डर के सापेक्ष पढ़ी और लिखी जाती हैं, जबकि प्रॉम्प्ट फ़ाइलें और स्क्रिप्ट रिपॉज़िटरी के सापेक्ष ही रहती हैं।

- **ट्रैकर ओवरराइड:** आप `CAREER_OPS_TRACKER` सेट करके आवेदन ट्रैकर फ़ाइल का पाथ सीधे भी बदल सकते हैं।
- **लेखन:** सभी लेखन ऑपरेशन (जैसे मर्ज) प्रामाणिक रूप से `{DATA_ROOT}/data/applications.md` को लक्षित करते हैं।
- **स्कैनर कॉन्फ़िग:** `portals.yml` को `{DATA_ROOT}/portals.yml` पर पढ़ा और सत्यापित किया जाता है, इसलिए `node validate-portals.mjs` वही फ़ाइल जाँचता है जो `scan.mjs` पढ़ता है।
- **बनाए गए दस्तावेज़:** अनुकूलित CV और कवर लेटर `{DATA_ROOT}/output/` के अंदर लिखे जाते हैं, और उन्हें किसी रिपोर्ट से जोड़ने वाला PDF मैनिफ़ेस्ट `{DATA_ROOT}/data/pdf-index.tsv` में रहता है। जब तक `CAREER_OPS_TRACKER` सेट नहीं है, इन लेखनों की सीमा तय करने वाला ट्रैकर वर्कस्पेस डेटा रूट है, चेकआउट नहीं।
- **ट्रैकर ओवरराइड के साथ PDF:** `generate-pdf.mjs` वर्कस्पेस तय करने से पहले `CAREER_OPS_TRACKER` को रिज़ॉल्व करता है, इसलिए ओवरराइड सेट होने पर वर्कस्पेस वह फ़ोल्डर होता है जिसमें वह ट्रैकर है (या उसके ऊपर वाला फ़ोल्डर, जब ट्रैकर किसी `data/` फ़ोल्डर में हो)। तब CV का HTML और हर PDF उसी वर्कस्पेस के अंदर होने चाहिए, और मैनिफ़ेस्ट उसकी `data/pdf-index.tsv` में चला जाता है। कवर लेटर अब भी `{DATA_ROOT}/output/` को ही लक्षित करते हैं, इसलिए जब वह फ़ोल्डर ट्रैकर के वर्कस्पेस से बाहर हो, तो उन्हें अस्वीकार कर दिया जाता है।
- **कोड लेयर अपनी जगह रहती है:** `node_modules/`, `providers/`, `modes/` और ख़ुद स्क्रिप्ट हमेशा रिपॉज़िटरी के सापेक्ष रिज़ॉल्व होते हैं, डेटा रूट के सापेक्ष कभी नहीं।

Go डैशबोर्ड TUI, Node.js स्क्रिप्ट और AI एजेंट मोड सभी इस रेज़ोल्यूशन क्रम का अपने आप पालन करते हैं।

## अक्सर पूछे जाने वाले प्रश्न (FAQ)

**career-ops क्या है?**
career-ops ([career-ops.org](https://career-ops.org), जिसे **careerops** भी कहा जाता है) एक ओपन सोर्स AI जॉब सर्च है जो आपकी AI कोडिंग CLI (Claude Code, Codex, OpenCode और अन्य) में लोकल चलती है और हर फ़ैसला आप पर छोड़ती है। यह आपके CV के मुक़ाबले जॉब ऑफ़र का मूल्यांकन करती है, ATS-अनुकूलित PDF बनाती है, संपर्क के लिए सही व्यक्ति ढूँढती है, और सब कुछ एक जगह ट्रैक करती है: अंतिम फ़ैसला हमेशा आपका है। यह [CareerOps घोषणापत्र](https://career-ops.org/manifesto) का पहला संदर्भ कार्यान्वयन है।

**क्या अनुकूलित CV कुछ गढ़ सकता है?**
नहीं गढ़ना चाहिए, और प्रॉम्प्ट यही कहते हैं: दोबारा लिखो, कभी गढ़ो मत। `generate-pdf` ऐसे CV को रोक देता है जिसके आँकड़े या तथ्य आपके स्रोतों में नहीं हैं, जब तक आप `--skip-fact-check` न दें। `pdf` मोड `cv-title-check.mjs` भी चलाता है, जो अनुकूलित CV के हर पद के नाम की तुलना उसी नौकरी के लिए cv.md में दिए पद के नाम से करता है (कंपनी और तारीखों से मिलाकर), और जो भी अलग हो उसे रखने या वापस बदलने के बारे में आपसे पूछता है। यह सिर्फ़ चेतावनी देता है, रोकता नहीं, क्योंकि पद के नाम को अलग ढंग से लिखना कभी-कभी आपका फ़ैसला होता है। दोबारा लिखे गए शब्दों को अभी कुछ भी नहीं परखता: [#1411](https://github.com/career-ops-hq/career-ops/issues/1411) (सत्यता जाँच जो विफल होने पर रोक दे) इसे ट्रैक करता है। तब तक, भेजने से पहले हर CV पढ़ें। [क़ानूनी अस्वीकरण](LEGAL_DISCLAIMER.md) यही बात ज़्यादा शब्दों में कहता है।

**क्या मैं career-ops मुफ़्त में, या सस्ते / लोकल मॉडल पर चला सकता हूँ?**
हाँ। career-ops CLI-निरपेक्ष है और मुफ़्त और लोकल मॉडल पर चलता है (OpenRouter के मुफ़्त मॉडल, Ollama, या कोई भी OpenAI-संगत एंडपॉइंट), इसलिए आप किसी पेड सब्सक्रिप्शन से बँधे नहीं हैं। पूरे सेटअप के लिए [docs/RUNNING_ON_A_BUDGET.md](docs/RUNNING_ON_A_BUDGET.md) देखें।

**मैं Claude Pro/Max के लिए भुगतान करता हूँ लेकिन career-ops API क्रेडिट खा रहा है। क्यों?**
क्योंकि आपके एनवायरनमेंट में मौजूद `ANTHROPIC_API_KEY` आपके लॉग-इन सब्सक्रिप्शन पर वरीयता पाता है: CLI उस key का इस्तेमाल करती है और प्रति टोकन बिल करती है। `echo $ANTHROPIC_API_KEY` चलाएँ, और अगर कुछ छपे तो उसे अपनी शेल प्रोफ़ाइल से हटाएँ, टर्मिनल दोबारा शुरू करें और `/login` चलाएँ। बैच मोड अपवाद है, क्योंकि `claude -p` वर्कर्स इंटरैक्टिव लॉगिन इस्तेमाल नहीं करते: एक बार `claude setup-token` चलाएँ और नतीजे को `CLAUDE_CODE_OAUTH_TOKEN` के रूप में एक्सपोर्ट करें। पूरी प्रक्रिया [docs/RUNNING_ON_A_BUDGET.md](docs/RUNNING_ON_A_BUDGET.md#2b-already-paying-for-a-subscription-make-sure-you-are-using-it) में।

**career-ops किन AI CLI के साथ काम करता है?**
career-ops ओपन Agent Skill Standard के ज़रिए किसी भी प्रमुख AI कोडिंग CLI (Claude Code, Codex, Gemini / Antigravity, OpenCode, Grok, Qwen और अन्य) पर चलता है, इसलिए यह कभी किसी एक वेंडर से बँधा नहीं है। जो CLI आपके पास पहले से है वही इस्तेमाल करें।

**Windows पर career-ops कैसे इंस्टॉल करूँ?**
career-ops Windows पर चलता है। प्लेटफ़ॉर्म-विशिष्ट सेटअप और ज्ञात दिक़्क़तें (Git Bash खोज, लाइन एंडिंग, Task Scheduler) [docs/WINDOWS.md](docs/WINDOWS.md) में हैं। अगर इंस्टॉल के दौरान symlink त्रुटि से स्किल लोड न हों, तो समाधान [docs/FAQ.md](docs/FAQ.md) में है। पूरे चरण [docs/SETUP.md](docs/SETUP.md) में हैं।

**क्या career-ops मेरे लिए नौकरियों में अपने आप आवेदन करता है?**
नहीं। career-ops एक फ़िल्टर है, अंधाधुंध ऑटो-आवेदन करने वाला टूल नहीं। AI मूल्यांकन, रैंकिंग और ड्राफ़्ट करता है; आप समीक्षा और फ़ैसला करते हैं। यह ड्राफ़्ट बनाता है और फ़ॉर्म भरता है; सबमिट कभी नहीं करता। आप Submit दबाते हैं। यही human-in-the-loop डिज़ाइन पूरी बात है।

**क्या career-ops मुफ़्त और ओपन सोर्स है?**
हाँ। career-ops मुफ़्त और ओपन सोर्स है, और उम्मीदवार के लिए हमेशा रहेगा। यह [CareerOps घोषणापत्र](https://career-ops.org/manifesto) का पहला संदर्भ कार्यान्वयन है। इसे पढ़ें, और अगर यह वही कहता है जो आप मानते हैं, तो हस्ताक्षर करें।
