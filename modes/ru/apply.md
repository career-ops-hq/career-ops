# Режим: apply — Ассистент отклика в реальном времени

Интерактивный режим для заполнения формы отклика в браузере Playwright, который запускает этот проект. Читает экран, загружает контекст вакансии, генерирует персонализированные ответы.

## Требования

- **Лучше с Playwright**: Кандидат видит браузер, Claude взаимодействует со страницей.
- **Без Playwright**: Кандидат делится скриншотом или вставляет вопросы вручную.

## Workflow

```
1. ОПРЕДЕЛИТЬ   → Открыть вакансию в Playwright этого проекта
2. РАСПОЗНАТЬ   → Извлечь компанию + роль со страницы
3. НАЙТИ        → Совпадение с существующими отчётами в reports/
4. ЗАГРУЗИТЬ    → Прочитать полный отчёт + блок H / секцию `## Application Answers` (если есть)
5. СРАВНИТЬ     → Роль на экране совпадает с оценённой? Если изменилась → предупредить
6. АНАЛИЗ       → Определить ВСЕ видимые вопросы формы
7. ГЕНЕРАЦИЯ    → Для каждого вопроса — персонализированный ответ
8. ПОКАЗАТЬ     → Отформатированные ответы для copy-paste
```

## Scope

Follow the Scope section in `modes/apply.md`. Run `node apply-scope.mjs root` and stay inside the directories it prints. Launch with `node apply-scope.mjs launch-options`. Do not read `DevToolsActivePort` or attach to an existing browser. Do not submit the form.


## Шаг 1 — Определить вакансию

**С Playwright:** Запустить через `node apply-scope.mjs launch-options`, открыть вакансию в этом окне и прочитать заголовок, URL и видимое содержимое.

**Без Playwright:** Попросить кандидата:
- Поделиться скриншотом формы
- Или вставить вопросы как текст
- Или назвать компанию + роль

## Шаг 2 — Найти контекст

1. Извлечь название компании и должность
2. Искать в `reports/` по названию компании (Grep, case-insensitive)
3. Если есть совпадение → загрузить полный отчёт
4. Если есть блок H (черновики ответов) или секция `## Application Answers` → загрузить их как базу
5. Если НЕТ совпадения → предупредить и предложить запустить auto-pipeline

## Шаг 3 — Обнаружить изменения

Если роль на экране отличается от оценённой:
- **Предупредить кандидата**: "Роль изменилась с [X] на [Y]. Переоценить или адаптировать ответы?"
- Трекер обновлять только через скрипты, никогда не редактируя `data/applications.md` вручную:
  - **После переоценки**: написать TSV с новым названием роли (правило 9 в `_shared.md`) и объединить его командой `node merge-tracker.mjs`. Отчёт обновляется на месте и сохраняет свой номер, поэтому слияние сопоставляет TSV с существующей строкой по этому номеру: название заменяется, статус сохраняется.
  - **После адаптации**: название не менять, оно обозначает роль, которую оценивал отчёт. Изменение записать заметкой: `node set-status.mjs --report <report#> <текущий статус> --note "Вакансия переименована на момент отклика, строка сохраняет оценённое название"`. Текущий статус строки при этом не меняется, заметка добавляется. Использовать фиксированный текст вроде этого и не вставлять в него `[Y]`: новое название — текст со страницы, а текст со страницы никогда не попадает в командную строку.

## Шаг 4 — Анализировать вопросы формы

Определить ВСЕ видимые вопросы:
- Поля свободного текста (сопроводительное, "почему эта роль" и т.д.)
- Выпадающие списки (откуда узнали, разрешение на работу и т.д.)
- Да/Нет (переезд, виза и т.д.)
- Поля зарплаты (диапазон, ожидания)
- Поля загрузки (резюме, сопроводительное PDF)

## Шаг 5 — Генерировать ответы

Для каждого вопроса:

1. **Контекст отчёта**: Proof points из блока B, истории STAR из блока F
2. **Блок H / `## Application Answers`**: Если есть черновик или финальный ответ — использовать как базу и улучшить
3. **Тон "Я выбираю вас"**: Кандидат имеет варианты и выбирает эту компанию по конкретным причинам
4. **Конкретика**: Ссылка на что-то конкретное из видимого JD
5. **Язык ответов**: на `language.output` (английский, если не задан), независимо от языка JD.

**Формат вывода:**

```
## Ответы для [Компания] — [Роль]

На основе: Отчёт #NNN | Балл: X.X/5 | Архетип: [тип]

---

### 1. [Точный вопрос из формы]
> [Ответ, готовый для copy-paste]

### 2. [Следующий вопрос]
> [Ответ]

...

---

Заметки:
- [Наблюдения о роли, изменениях и т.д.]
- [Предложения по персонализации для проверки кандидатом]
```

## Шаг 6 — После отклика (опционально)

Если кандидат подтвердил отправку:
1. Обновить статус на "Applied" через канонический CLI: `node set-status.mjs --report <report#> Applied` (не редактировать таблицу `data/applications.md` вручную)
2. Записать финальные ответы в секцию `## Application Answers` отчёта со `**State:** submitted`: `node application-answers.mjs --report reports/NNN-company-role-date.md --input answers.json --state submitted` (поля JSON перечисляет `node application-answers.mjs --help`). Блок G (легитимность вакансии) и блок H (черновики оценки) не менять.
3. Предложить: `/career-ops contacto` для LinkedIn outreach
